# چک‌لیست تست دستی روی دستگاه

تاریخ: ۲۰۲۶-۱۰-۲۱ · وضعیت: پیشنهادی

این چک‌لیست هنوز اجرا نشده است. هیچ موردی در این سند «تست‌شده» نیست. نتیجه هر مورد باید با تاریخ، دستگاه، نسخه اندروید و هش بیلد ثبت شود.

## ۱. پیش‌نیازها

- macOS یا Linux با `adb` در PATH.
- JDK 17 و Android SDK 36.
- دستگاه یا امولاتور با اندروید ۸ (API 26) یا بالاتر؛ برای تست مجوز اعلان، اندروید ۱۳ (API 33) یا بالاتر.
- یک دستگاه AOSP (مثلاً Pixel) و در صورت امکان یک دستگاه سامسونگ یا شیائومی برای تست OEM.
- حالت توسعه و USB debugging روشن.
- برای دسترسی به فایل‌های اپ، بیلد debug لازم است (`run-as` روی بیلد release کار نمی‌کند).

## ۲. ساخت و نصب

```bash
cd /Users/aminshojaei/AndroidStudioProjects/carchi/android
./gradlew assembleDebug
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n app.carchi/.MainActivity
```

- خروجی APK: `android/app/build/outputs/apk/debug/app-debug.apk`
- پکیج: `app.carchi`
- اکتیویتی اصلی: `app.carchi/.MainActivity`

برای گرفتن اسکرین‌شات:

```bash
mkdir -p /tmp/carchi-test-2026-10-21
adb exec-out screencap -p > /tmp/carchi-test-2026-10-21/01-onboarding.png
```

برای پاک کردن کامل داده و شروع تازه:

```bash
adb shell pm clear app.carchi
```

> `pm clear` هم `state.json` و هم `state.bak.json` را پاک می‌کند. قبل از اجرا، اگر داده لازم است، از آن کپی بگیرید.

## ۳. دسترسی به فایل‌های وضعیت

مسیرها داخل `filesDir` اپ هستند:

- `files/state.json`
- `files/state.bak.json`
- `files/state.tmp.json` (فقط در حین نوشتن)
- `files/state.corrupt-<timestamp>.json`
- `files/state.deleted-<timestamp>.json`
- `files/state.deleted-<timestamp>.bak.json`

دستورها:

```bash
# فهرست فایل‌ها
adb shell run-as app.carchi ls -l files

# خواندن وضعیت روی کامپیوتر
adb exec-out run-as app.carchi cat files/state.json > /tmp/carchi-state.json

# کپی سالم قبل از دستکاری
adb shell "run-as app.carchi cp files/state.json files/state.good.json"

# خراب کردن state.json
adb shell "run-as app.carchi sh -c 'echo {broken > files/state.json'"

# حذف بکاپ
adb shell "run-as app.carchi rm -f files/state.bak.json"

# حذف فقط فایل اصلی (برای تست بازیابی از بکاپ)
adb shell "run-as app.carchi rm -f files/state.json"

# بازگرداندن فایل سالم
adb shell "run-as app.carchi sh -c 'cat files/state.good.json > files/state.json'"

# بستن و باز کردن اپ
adb shell am force-stop app.carchi
adb shell am start -n app.carchi/.MainActivity
```

نکته: `run-as` فقط روی بیلد debug کار می‌کند و باید نام پکیج دقیقاً `app.carchi` باشد.

فایل ۰.۱ این فیلدها را ندارد: `schema`، `car.id`، `overrides`، `reminders`، `catalogVersion`، `lastNotified`. نمونه قابل استفاده:

```json

    "modelId": "p206t2",
    "year": 1398,
    "km": 121500,
    "startedAt": 1750000000000
  },
  "services": {
    "oil": { "km": 118000, "date": 1750000000000 },
    "airfilter": { "km": 112000, "date": 1747000000000 }

  "events": [
```

ذخیره در `/tmp/carchi-state-v01.json` و تزریق:

```bash
  },
  "events": [
    { "partId": "oil", "km": 118000, "date": 1750000000000, "cost": 850000, "type": "done" },
    { "partId": "airfilter", "km": 112000, "date": 1747000000000, "cost": 0, "type": "baseline" }

JSON

adb shell pm clear app.carchi
adb shell am start -n app.carchi/.MainActivity
adb shell am force-stop app.carchi
adb shell "run-as app.carchi sh -c 'cat > files/state.json'" < /tmp/carchi-state-v01.json
adb shell am start -n app.carchi/.MainActivity
```

> یک بار باز کردن اپ قبل از تزریق لازم است تا پوشه `files/` ساخته شود؛ لازم نیست فرم را پر کنید. از نسخه ۰.۳ نصب تازه مستقیماً آنبوردینگ نشان می‌دهد و پوشه `files/` با اولین ذخیره ساخته می‌شود.

سپس وضعیت را بخوانید و بررسی کنید:

```bash
adb exec-out run-as app.carchi cat files/state.json > /tmp/carchi-state-after.json
```

انتظار: `schema = 2`، `car.id = "car1"`، `overrides = {}`، `catalogVersion = 2`، `reminders` با مقادیر پیش‌فرض، `lastNotified = {}` و `services` شامل همه ۱۳ قطعه. قطعاتی که در فایل ۰.۱ نبودند با کیلومتر فعلی و تاریخ امروز اضافه می‌شوند. رویداد `baseline` باید حذف شده باشد.

### نکته مهم مهاجرت واقعی

نسخه ۰.۱ با `applicationId = "app.carcare"` و نسخه ۰.۲ با `app.carchi` ساخته شده است. بنابراین نصب ۰.۲ روی ۰.۱ **آپدیت درجا نیست** و داده ۰.۱ به‌طور خودکار منتقل نمی‌شود. برای تست واقعی:


در ۰.۱ یک خودرو ثبت کنید، سپس فایل واقعی را بردارید:

```bash

```

حالا ۰.۲ را نصب کنید (هر دو پکیج کنار هم می‌مانند) و فایل را تزریق کنید:


این مسیر، شکل واقعی داده ۰.۱ را بدون root تست می‌کند. تست نباید انتظار داشته باشد که نصب ۰.۲ داده ۰.۱ را خودکار ببیند.

## ۵. دستورهای اعلان

```bash
# مجوز (اندروید ۱۳+)
adb shell pm revoke app.carchi android.permission.POST_NOTIFICATIONS
adb shell pm grant app.carchi android.permission.POST_NOTIFICATIONS

# اعلان‌های ثبت‌شده
adb shell dumpsys notification --noredact | grep -A 20 'app.carchi' | head -80

# کارهای WorkManager
adb shell dumpsys jobscheduler | grep -B 3 -A 20 'app.carchi' | head -100
```

در خروجی `jobscheduler`، شناسه کار را پیدا کنید (قالب `JOB #u0a.../<id>`) و برای اجرای فوری:

```bash
adb shell cmd jobscheduler run -f app.carchi <JOB_ID>
```

`-f` محدودیت‌ها را نادیده می‌گیرد؛ برای تست گیت ۲۰ ساعته و متن اعلان مناسب است، ولی برای تست `battery not low` معتبر نیست.

برای شبیه‌سازی Doze:

```bash
adb shell dumpsys battery unplug
adb shell dumpsys deviceidle force-idle
# پس از تست
adb shell dumpsys deviceidle unforce
adb shell dumpsys battery reset
```

برای استثنا کردن اپ از بهینه‌سازی باتری (فقط برای تست):

```bash
adb shell dumpsys deviceidle whitelist +app.carchi
adb shell dumpsys deviceidle whitelist -app.carchi
```

## ۶. چک‌لیست اجرایی

### A. نصب، آنبوردینگ، ماندگاری

- [ ] **A1. نصب تازه:** `pm clear` و باز کردن اپ. مستقیماً صفحه «ماشینت را ثبت کن» بدون Splash، بدون ثبت‌نام و بدون صفحه بازیابی بیاید.
- [ ] **A2. اعتبارسنجی فرم:** بدون انتخاب مدل «شروع» بزن؛ خطای مدل. سال ۱۲۰۰ و کیلومتر منفی را وارد کن؛ خطای مربوطه. سال و کیلومتر با ارقام فارسی وارد شوند و پذیرفته شوند.
- [ ] **A3. سلب مسئولیت:** متن «بازه‌ها تخمینی‌اند» در آنبوردینگ و پایین داشبورد دیده شود.
- [ ] **A4. داشبورد اولیه:** با مدل بدون زنجیر (مثلاً ۲۰۶ تیپ ۲) ۱۳ قطعه دیده شود؛ همه با تاریخ امروز و کیلومتر ورودی؛ برچسب «تخمینی» روی همه؛ قطعات ایمنی برچسب «ایمنی» داشته باشند. با یک مدل `chain` (مثلاً ۲۰۰۸) تسمه تایم نمایش داده نشود.
- [ ] **A5. ماندگاری:** اپ را force-stop و دوباره باز کن؛ خودرو و کیلومتر برگردند. `state.json` وجود داشته باشد.
- [ ] **A6. حذف فایل اصلی:** دست‌کم دو ذخیره موفق انجام بده تا بکاپ ساخته شود؛ `state.json` را حذف کن (بکاپ را دست نزن)؛ اپ باید داده بکاپ را بازیابی کند و `state.json` دوباره ساخته شود؛ آنبوردینگ نیاید.
- [ ] **A7. نبود هر دو فایل:** `state.json` و `state.bak.json` را حذف کن؛ اپ صفحه بازیابی نشان دهد، نه crash؛ با «شروع تازه» آنبوردینگ باز شود.

### B. کیلومتر، انجام سرویس، تاریخچه

- [ ] **B1. +۱۰۰۰:** «ثبت کیلومتر» → «+ ۱٬۰۰۰» → ثبت؛ عدد ۱٬۰۰۰ بیشتر شود و در فایل ذخیره شود.

- [ ] **B3. انجام شد با هزینه:** یک قطعه → «انجام شد» → کیلومتر و هزینه؛ وضعیت سبز و ردیف تاریخچه با هزینه.
- [ ] **B4. مجموع هزینه:** مجموع بالای تاریخچه با مجموع ردیف‌ها بخواند؛ ارقام فارسی و جداکننده «٬».
- [ ] **B5. اصلاح آخرین سرویس:** «آخرین سرویس را اصلاح کن» → کیلومتر جدید؛ تاریخ امروز ثبت شود و وضعیت بازمحاسبه شود.
- [ ] **B6. کیلومتر کمتر در انجام شد:** عدد کمتر از کیلومتر فعلی وارد کن؛ پذیرفته شود، سرویس ثبت شود، ولی کیلومتر داشبورد کمتر نشود. این رفتار را به‌عنوان شکاف محصول ثبت کن.
- [ ] **B7. بنر وضعیت:** با یک قطعه گذشته، بنر قرمز؛ با فقط نزدیک، بنر نارنجی؛ با همه سالم، بنر سبز.
- [ ] **B8. تاریخچه خالی:** پس از `pm clear`، «شروع تازه» و ثبت خودرو، تاریخچه پیام «هنوز چیزی ثبت نشده» نشان دهد؛ هیچ رویداد `baseline` ساخته نشود.
- [ ] **B9. دفترچه راهنما:** با مدل ۲۰۶ تیپ ۲، در تنظیمات دکمه «دفترچه راهنمای این خودرو (PDF)» دیده شود و مرورگر باز شود. با مدل تیبا دکمه دیده نشود.

### D. ذخیره‌سازی، خرابی، بازیابی

- [ ] **D1. خرابی با بکاپ سالم:** پس از ثبت خودرو، یک تغییر ذخیره کن (تا بکاپ ساخته شود)؛ `state.good.json` بساز؛ `state.json` را خراب کن؛ اپ را باز کن. اپ باید با داده بکاپ بالا بیاید، یک `state.corrupt-*.json` داشته باشد و `state.json` دوباره معتبر باشد.
- [ ] **D2. بکاپ سالم بعد از بازیابی:** بعد از D1 یک تغییر ذخیره کن؛ بررسی کن `state.bak.json` هنوز قابل decode باشد و محتوای خراب نداشته باشد.
- [ ] **D3. خرابی هر دو:** `state.json` را خراب و `state.bak.json` را حذف یا خراب کن؛ اپ را باز کن. صفحه «فایل داده‌ها خوانده نشد» و دکمه «شروع تازه»؛ هیچ نوشتن خودکار روی `state.json` یا بکاپ (فقط انتقال فایل خراب).
- [ ] **D4. شروع تازه:** دکمه را بزن؛ آنبوردینگ باز شود؛ `state.json` و `state.bak.json` با نام `state.deleted-*` آرشیو شده باشند؛ `state.corrupt-*` باقی بماند.
- [ ] **D5. schema جدیدتر:** فایل معتبر با `"schema": 3` تزریق کن؛ اپ باز شود، داشبورد بیاید، در تنظیمات بنر «ذخیره‌سازی قفل است» دیده شود؛ یک تغییر بده و اپ را ببند؛ تغییر نباید در فایل باشد و پیام «ذخیره نشد» بیاید.
- [ ] **D6. نوشتن اتمیک:** در حین ذخیره، اپ را force-stop کن (چند بار تکرار کن)؛ `state.json` باید قابل خواندن بماند و `state.tmp.json` تنها نماند.
- [ ] **D7. فایل موقت:** پس از ذخیره موفق، `state.tmp.json` وجود نداشته باشد.
- [ ] **D8. فایل خراب متعدد:** دو بار با فایل خراب اپ را باز کن؛ باید کپی‌های `state.corrupt-*` با نام‌های متفاوت ساخته شوند.
- [ ] **D9. شکست ذخیره:** در حالت `readOnly` (مثلاً `schema = 3`) کیلومتر را عوض کن؛ پیام «ذخیره نشد»؛ مقدار قبلی در UI بماند و فایل تغییر نکند.
- [ ] **D10. بازیابی از بکاپ بدون فایل اصلی:** با وجود بکاپ سالم، `state.json` را حذف کن و اپ را باز کن؛ داده بکاپ برگردد. این مورد را با A6 یکی می‌توان کرد.

## ۹. محدودیت‌های این چک‌لیست

- هیچ تست خودکار یا unit test در پروژه وجود ندارد؛ همه موارد دستی‌اند.

- اسکرین‌شات‌ها ممکن است کیلومتر یا اطلاعات شخصی را نشان دهند؛ قبل از اشتراک، بازبینی کنید.
