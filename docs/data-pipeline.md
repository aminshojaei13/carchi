# پایپ‌لاین داده کاتالوگ خودرو

> این سند مربوط به اسکریپت یک‌باره `tools/import_khodrobank.py` است که کاتالوگ مدل‌های خودرو را از
> `khodrobank.com` می‌خواند و فایل `data/models.json` را می‌سازد.
> این پایپ‌لاین در زمان اجرای اپ دخالتی ندارد؛ خروجی آن یک فایل ثابت است که در بسته اپ قرار می‌گیرد.

---

## ۱. هدف و خروجی

| مورد | مقدار |
| --- | --- |
| ورودی | `https://www.khodrobank.com/sitemap/cars_sitemap.xml.gz` |
| خروجی داده | `data/models.json` |
| خروجی گزارش | `data/import-report.md` |
| وابستگی | فقط کتابخانه استاندارد پایتون ۳ (`urllib`, `gzip`, `re`, `html`, `json`, `concurrent.futures`, `argparse`) |
| نوع اجرا | یک‌باره / دستی (نه Cron، نه سرور) |

اسکریپت هیچ فایل دیگری نمی‌نویسد و هیچ داده‌ای را به اپ تزریق نمی‌کند؛ تنها دو فایل بالا را می‌سازد.

---

## ۲. سیاست حقوقی و دامنه داده

اصل سخت‌گیرانه: **فقط فکت‌های عددی و برچسب‌های کوتاه.**

| مجاز (ذخیره می‌شود) | ممنوع (ذخیره نمی‌شود) |
| --- | --- |
| حجم موتور (cc)، قدرت (hp)، گشتاور (Nm) | متن مقاله، توضیحات، معرفی مدل |
| گیربکس، نوع سوخت، کلاس بدنه، وزن | نظرات کاربران، امتیازها، مزایا/معایب |
| برند، نام مدل، URL منبع، زمان برداشت | عکس، لوگو، گالری، فایل PDF |
| شناسه پایدار مدل | متن مقایسه با رقبا، پرسش و پاسخ |

- دامنه فقط `www.khodrobank.com` است؛ اسکریپت لینک‌های خارجی را دنبال نمی‌کند.
- `robots.txt` سایت فقط `/*utm_`، `/tags/` و `/Authors/` را ممنوع کرده و مسیر `/cars/` آزاد است.
- درخواست‌ها با User-Agent معمولی مرورگر و تأخیر ۰.۳–۰.۵ ثانیه انجام می‌شوند؛ حداکثر ۴ worker.
- خروجی هیچ متن بلندی ندارد: مقادیر متنی حداکثر ۳۰ کاراکتر و صرفاً دسته‌بندی‌های کوتاه‌اند.
- `license_note` در JSON همین سیاست را ثبت می‌کند: `facts only; no text/images/reviews`.

> این سند جای مشاوره حقوقی نیست. اگر قرار است داده در محصول منتشرشده توزیع شود، شرایط استفاده
> سایت منبع باید جداگانه بررسی شود. طراحی فعلی برای کمینه‌کردن ریسک است: بدون متن، بدون عکس،
> بدون نظر کاربر.

## ۳. ساختار داده

`data/models.json`:

```json
{
  "generated_at": "2026-10-21T10:00:00Z",
  "source": "khodrobank.com",
  "license_note": "facts only; no text/images/reviews",
  "models": [
    {
      "id": "kb-198",
      "brand": "ایران خودرو",
      "name": "رانا",
      "chain": null,
      "source_url": "https://www.khodrobank.com/cars/...",
      "retrieved_at": "2026-10-21T10:00:00Z",
      "specs": {
        "engine_cc": 1598,
        "power_hp": 113,
        "torque_nm": 140,
        "transmission": "دستی",
        "fuel": "بنزین",
        "body": "سدان",
        "weight_kg": 1050
      }
    }
  ]
}
```

### فیلدها

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `id` | string | شناسه پایدار. اگر برند و مدل لاتین باشند: `slug(brand)-slug(model)-{id}`؛ در غیر این صورت `kb-{id}` سایت. |
| `brand` | string | برند، از مسیر URL (unquote، خط تیره → فاصله، یکسان‌سازی ک/ی عربی). |
| `name` | string | نام مدل، از مسیر URL؛ پیشوند برند حذف می‌شود. |
| `chain` | null | وضعیت تسمه تایم. **در منبع وجود ندارد؛ همیشه `null` می‌ماند و حدس زده نمی‌شود.** |
| `source_url` | string | آدرس همان صفحه مدل. |
| `retrieved_at` | string | زمان برداشت (ISO 8601 UTC). |
| `specs.engine_cc` | int \| null | حجم موتور به سی‌سی. |
| `specs.power_hp` | int \| null | قدرت موتور به اسب بخار (kW در صورت وجود تبدیل می‌شود). |
| `specs.torque_nm` | int \| null | گشتاور به نیوتن‌متر. |
| `specs.transmission` | string \| null | یکی از `دستی`، `اتوماتیک`، `CVT`، `دوکلاچه`، `تکسرعته`، `DHT`. |
| `specs.fuel` | string \| null | `بنزین`، `گازوئیل`، `دوگانه سوز`، `هیبرید`، `برقی`. |
| `specs.body` | string \| null | `سدان`، `هاچ بک`، `شاسی بلند`، `کراس اوور`، `کوپه`، `کروک`، `پیکاپ`، `ون`، `فست بک`، `لیفت بک`، `استیشن`. |
| `specs.weight_kg` | int \| null | وزن خالی به کیلوگرم. |

کلیدهای موجود در `specs` فقط وقتی نوشته می‌شوند که مقدار واقعی پیدا شود؛ فیلد پیدا‌نشده حذف
می‌شود (در اپ به‌عنوان `null`/ناموجود خوانده شود). هیچ‌جا مقدار پیش‌فرض یا حدسی نوشته نمی‌شود.

### شناسه پایدار

`id` از شماره مدل در URL سایت ساخته می‌شود (`kb-{id}`)، چون نام‌ها فارسی‌اند و transliterate
نمی‌شوند. شماره مدل در sitemap یکتاست. اگر روزی مدلی با نام لاتین خالص اضافه شود، قالب
`brand-model-id` استفاده می‌شود. در هر دو حالت `id` بین اجراها تغییر نمی‌کند.

## ۴. نحوه اجرا

```bash
# راهنما و همه گزینه‌ها
python3 tools/import_khodrobank.py --help

# اجرای کامل (حدود ۶۳۶ صفحه، چند دقیقه)
python3 tools/import_khodrobank.py

# تست سریع روی ۲۰ صفحه، بدون دست‌زدن به خروجی اصلی
python3 tools/import_khodrobank.py --limit 20 --out /tmp/models.json --report /tmp/report.md
```

### گزینه‌ها

| گزینه | پیش‌فرض | کاربرد |
| --- | --- | --- |
| `--sitemap-url` | sitemap رسمی | تغییر منبع فهرست |
| `--out` | `data/models.json` | مسیر خروجی JSON |
| `--report` | `data/import-report.md` | مسیر گزارش |
| `--workers` | `4` | تعداد دانلود هم‌زمان (سخت‌گیرانه حداکثر ۴) |
| `--delay` | `0.4` | تأخیر ادب‌آمیز هر درخواست (ثانیه، در بازه ۰.۳–۰.۵) |
| `--limit` | `0` | فقط N URL اول (۰ = همه) |
| `--resume` | خاموش | ادغام با خروجی موجود: فقط URLهای غایب یا بدون مشخصه دوباره گرفته می‌شوند |
| `--timeout` | `45` | مهلت هر درخواست |
| `--user-agent` | UA مرورگر | شناسه درخواست |
| `--quiet` | خاموش | لاگ کمتر |

اسکریپت در پایان کد خروج `0` می‌دهد اگر حداقل ۲۰۰ مدل ساخته شود؛ در غیر این صورت `1`.
خطاهای شبکه/پارس در گزارش ثبت و اجرا ادامه داده می‌شود (fail-soft).

## ۵. چطور دوباره اجرا کنیم (به‌روزرسانی)

1. مطمئن شوید `python3 --version` حداقل ۳.۸ است.
2. اسکریپت را اجرا کنید: `python3 tools/import_khodrobank.py`
3. `data/import-report.md` را بخوانید: درصد موفقیت و پوشش هر فیلد باید نزدیک اجرای قبلی باشد.
4. `data/models.json` را از نظر JSON معتبر و تعداد مدل بررسی کنید:

```bash
python3 -c "import json;d=json.load(open('data/models.json'));print(d['generated_at'],len(d['models']))"
```

اجرا **بازنویسی** است، نه ادغام. اگر مدلی از سایت حذف شود، از خروجی هم حذف می‌شود. برای
مقایسه نسخه‌ها، فایل قبلی را جدا نگه دارید یا از گیت استفاده کنید.

اگر اجرا وسط کار قطع شد یا چند صفحه خطای موقت دادند، بدون دانلود دوباره همه صفحات:

```bash
python3 tools/import_khodrobank.py --resume
```

`--resume` خروجی موجود را می‌خواند و فقط URLهایی را می‌گیرد که در فایل نیستند یا `specs` خالی
دارند؛ بقیه رکوردها دست‌نخورده می‌مانند. گزارش، آمار همان اجرا و پوشش کل کاتالوگ را جدا نشان
می‌دهد.

نکته: `--limit` برای تست است و خروجی ناقص می‌سازد؛ برای انتشار از اجرای کامل استفاده کنید.

## ۶. استخراج چگونه انجام می‌شود

چهار منبع ساختاریافته در هر صفحه خوانده می‌شود و اولویت‌بندی دارد:

1. **کاشی‌های مشخصات** (`car-single_topspecs_item`): کلاس بدنه، نوع جعبه دنده، حداکثر توان.
2. **کاشی‌های بالای صفحه** (`car-single_title_spec`): حجم موتور، مصرف سوخت.
3. **جدول مشخصات فنی** (`kb-tcl-hoder`): حداکثر گشتاور، وزن، حجم موتور، جعبه دنده.
4. **JSON-LD** (`schema.org/Car` و `EngineSpecification`): `fuelType`، `weight`،
   `vehicleTransmission`، `engineDisplacement`، `enginePower` — به‌عنوان منبع پشتیبان.

اگر یک فیلد در منبع اول نبود، از منبع بعدی پر می‌شود؛ در غیر این صورت خالی می‌ماند.
متن آزاد صفحه هرگز استخراج یا ذخیره نمی‌شود.

صفحه‌ای که هیچ‌کدام از این بلوک‌ها را ندارد (صفحه خطای نرم با کد ۲۰۰ یا تغییر قالب سایت) به‌عنوان
خطا در نظر گرفته و یک بار دیگر دریافت می‌شود؛ اگر باز هم خالی بود، در گزارش به‌عنوان ناموفق ثبت
می‌شود تا آمار موفقیت واقعی بماند.

## ۷. محدودیت‌های شناخته‌شده

- **بازه تعویض تسمه تایم از این منبع نمی‌آید.** سایت بازه کیلومتری/زمانی تعویض را به‌صورت
  ساختاریافته منتشر نمی‌کند. `chain` همیشه `null` است. برنامه تعویض قطعات باید از منبع دیگری
  (دفترچه سازنده یا داده تخصصی) بیاید.
- **PDF دفترچه راهنما لینک نشده است**؛ بنابراین از این پایپ‌لاین قابل استخراج نیست.
- «نوع سوخت» در HTML نمایشی برچسب ندارد و از JSON-LD خوانده می‌شود؛ اگر ساختار سایت تغییر کند،
  پوشش این فیلد اول از همه افت می‌کند. صفحه‌های قدیمی‌تر که اصلاً JSON-LD نوع `Car` ندارند،
  برای `fuel` مقدار `null` می‌گیرند (حدس زده نمی‌شود).
- مقدار قدرت/گشتاور ممکن است بین نسخه‌های تیپ و موتور متفاوت باشد؛ سایت برای هر تیپ یک صفحه
  جدا دارد و همان مقدار صفحه ثبت می‌شود.
- گشتاور و وزن فقط از جدول فنی می‌آیند؛ اگر صفحه‌ای جدول نداشته باشد، این دو خالی می‌مانند.
- داده یک اسنپ‌شات است؛ مدل‌های جدید تا اجرای بعدی اضافه نمی‌شوند.
- تعداد صفحات کم است (~۶۳۶) و اجرا عمداً کند و محترمانه است.

## ۸. عیب‌یابی

| نشانه | علت احتمالی | راه‌حل |
| --- | --- | --- |
| `cannot read sitemap` | قطعی شبکه یا تغییر آدرس sitemap | آدرس را با `--sitemap-url` بدهید |
| درصد موفقیت پایین | محدودیت موقت سایت یا timeout | `--workers 2` و `--delay 0.5` را امتحان کنید |
| پوشش یک فیلد صفر شد | تغییر HTML سایت | سلکتورهای بخش ۶ را به‌روز کنید |
| `validation problems` | شناسه تکراری یا مقدار متنی بلند | گزارش را بخوانید؛ رکورد مشکل‌دار نباید منتشر شود |
